# 42sh - [read the documentation here](https://leowz.github.io/42sh/)

A POSIX-flavoured shell implemented in C as a group project at 42 School.
The shell supports interactive line editing, command history, job control,
pipelines, redirections, and variable/environment management, all built from
scratch on top of a custom `libft` standard library.

The pipeline is: **line editor → lexer → parser → expander → executor**,
with job control and signal handling wired in at the executor level.

## LINKS: [Docs](https://leowz.github.io/42sh/docs/) & [Visualizer](https://leowz.github.io/42sh/viz/)

## Building

```bash
# Build the shell
make

# Build with AddressSanitizer + UBSan (debugging)
make debug

# Remove object files
make clean

# Remove everything (objects + binaries + generated docs)
make fclean

# Full rebuild from scratch
make re
```

> **Dependencies**: `gcc`, `libreadline-dev`, `libncurses-dev`

## Makefile reference

| Target | Description |
|---|---|
| `make` / `make all` | Build `42sh` |
| `make debug` | Build with ASAN, UBSan, and `-DDEBUG` |
| `make test` | Compile and run the unit test suite |
| `make docs` | Generate Doxygen man pages (`docs/core/` and `docs/test/`) |
| `make html` | Convert man pages to HTML and build `docs/pages.json` |
| `make serve` | Build HTML docs and serve them at `http://localhost:8080` |
| `make dclean` | Remove generated docs (preserves `docs/index.html`) |
| `make clean` | Remove object files |
| `make fclean` | Remove objects, binaries, and generated docs |
| `make re` | `fclean` then `all` |

## Documentation

API documentation is auto-generated by Doxygen and published to the
[`docs` branch](https://github.com/leowz/42sh/tree/docs) on every push to
`main`. GitHub Pages serves it as a browsable HTML site.

To build and browse locally:

```bash
make serve   # builds HTML docs then opens http://localhost:8080
```

## Test suite

Tests live in `tests/` and are compiled into a dedicated binary (`42sh_test`)
that is completely separate from the shell binary. `main.c` is excluded from
the test build so the shell's `main()` never conflicts with the test runner's.

### Running

```bash
make test
```

Output looks like:

```
=== 42sh Unit Tests ===

>>> test_dlist_suite
  PASS pointer is not null
  PASS size == 3
  PASS forward link 1→2
  ...

>>> test_list_suite
  ...

--- 42 passed, 0 failed ---
```

A non-zero failed count causes the binary to exit with status `1`, which
propagates through `make` so CI catches any regression.

### Framework - `minunit.h`

The test framework is a single header (`tests/minunit.h`) with no external
dependencies. It exposes three assertion macros and two runner macros:

| Macro | Purpose |
|---|---|
| `MU_ASSERT(msg, expr)` | Fail if `expr` is zero |
| `MU_ASSERT_INT(expected, actual)` | Fail if two `int` values differ |
| `MU_ASSERT_STR(msg, expected, actual)` | Fail if two strings differ (NULL-safe) |
| `MU_RUN(suite_fn)` | Run a suite function and print its name |
| `MU_SUMMARY()` | Print totals and return `0`/`1` to the OS |

### Adding a new test suite

1. Create `tests/test_mymodule.c` with a `void test_mymodule_suite(void)` function.
2. Guard unstable assertions with `#ifdef TEST_MYMODULE_ENABLED` while the
   implementation is still in progress.
3. Add `-DTEST_MYMODULE_ENABLED` to `TEST_FLAGS` in the root `Makefile`.
4. Forward-declare and call the suite in `tests/test_runner.c`:
   ```c
   void test_mymodule_suite(void);
   // ...
   MU_RUN(test_mymodule_suite);
   ```
5. Once all assertions are permanently green, remove the `#ifdef` guards and
   the `-D` flag - the suite then compiles and runs unconditionally.

## CI / CD

Every push and pull request runs `make test` on Ubuntu via GitHub Actions.
On `main`, a passing test job additionally triggers `make html` and deploys
the `docs/` directory to the `docs` branch for GitHub Pages.

See [`.github/workflows/ci.yml`](.github/workflows/ci.yml).
